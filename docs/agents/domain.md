# Domain Docs

本文件规定工程 Skills 在探索和修改仓库前如何读取领域文档。

## 探索前需要读取

- 根目录的 `CONTEXT.md`
- 如果根目录存在 `CONTEXT-MAP.md`，改为根据其中的映射读取与任务相关的上下文
- `docs/adr/` 中与当前任务相关的架构决策

如果这些文件不存在，应静默继续，不要仅因为缺少文件而建议提前创建。

`/domain-modeling` Skill 会在术语或决策真正确定时按需创建或更新领域文档。

## 当前布局

本仓库采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/
│   ├── adr/
│   └── agents/
└── src/
```

- `CONTEXT.md` 只记录领域词汇及应避免使用的同义词
- `docs/adr/` 记录难以逆转、存在真实取舍且缺少背景会令人困惑的架构决策
- `docs/agents/` 记录工程 Skills 的仓库级使用规则

## 使用领域词汇

Issue 标题、规格文档、重构建议、测试名称和代码设计应使用 `CONTEXT.md` 中定义的正式术语。

不得重新使用词汇表中明确列入 `_Avoid_` 的同义词。

如果需要的概念尚未出现在词汇表中，应先判断：

1. 是否正在引入项目并不需要的新概念
2. 是否确实存在需要通过 `/domain-modeling` 补充的领域词汇

## 处理 ADR 冲突

如果方案与现有 ADR 冲突，必须明确指出冲突，不得静默覆盖既有决定。

示例：

> 与 ADR-0007 的媒体存储方案冲突；建议重新讨论该决策，因为……
