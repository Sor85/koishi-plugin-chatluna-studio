# 虚拟 OneBot 机器人触发的模型请求不进记录库

模拟环境类插件（AI 测试空间、开发者观察窗）会注册一个 `platform` 为 `onebot`、`hidden` 为真的机器人，并用它派发真实 Koishi session。ChatLuna 照常走完整条对话链路、照常发出生命周期事件，于是这些模型请求在本插件采集所依赖的 fetch 边界（[ADR-0005](./0005-wrap-chatluna-fetch-for-model-request-records.md)）上与真实会话的请求完全一样，并且会像真实会话一样被归属（[ADR-0002](./0002-attribute-requests-from-chatluna-lifecycle-events.md)）、进入筛选可选值、参与轨迹聚合与预设证据定位。

**这些请求整条丢弃，不记录也不标记。** 记录库只有一个（[ADR-0001](./0001-keep-all-model-requests-in-one-library.md)），本插件的记录被当作真实会话的证据使用——预设页面靠它证明某个表达式在真实请求里展开成了什么。加一个「来源」维度会把模拟环境的概念重新引进这个只有一个记录库的模型里，而模拟出来的对话对预设定位没有任何证明力。丢弃发生在 `store.append` 之前：记录一旦写进去，列表、聚合、轨迹与定位都会把它当作真实请求，而记录上没有任何字段能事后把它认出来。

**判据是虚拟机器人的通用形状，不是某个插件。** `bot.hidden === true && bot.platform === 'onebot'`：对 UI 隐藏、OneBot action 通道由注册它的插件在自有场景里实现。按包名或 selfId 认会在换插件、改配置时静默失效，而真实适配器不会把 `hidden` 置真——控制台需要在机器人列表里显示它们，所以这个判据不会误伤真实会话。缺任何一半都不算：只看 `hidden` 会连别的平台一起误伤，只看 `onebot` 会把全部真实 OneBot 会话丢掉。

**只在「在跑的对话轮全是虚拟的」时丢弃。** 虚拟轮与真实轮并发时，fetch 边界分不出这次请求是哪一边发的：丢掉会连真实会话的证据一起丢，归属会把模拟请求挂到真实会话上，两者都比多留一条待人工对照的未归属记录更贵。这是 ADR-0002 里同一个取舍的延伸，代价是模拟环境与真实对话同时在跑时会漏进未归属。反过来，判据不能写成「恰好一轮且这一轮是虚拟的」：模拟环境里跑多轮时全部会漏回记录库。

判定住在会话跟踪器里而不是采集器里：采集器只知道「拿到候选就写归属」，而「几轮算可判定」「哪种机器人不该记」都是会话跟踪自己的规则。跟踪器因此一次给出归属候选与 `virtualOnly` 两个结果，采集器不必分两次读同一份状态。同理，虚拟轮的上游错误也不再回填（[ADR-0010](./0010-attach-chatluna-errors-to-model-requests.md)）：那一轮的请求从未进过记录库，回填只会白扫一遍。
