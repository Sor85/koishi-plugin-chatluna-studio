# 模型请求记录住在同一个记录库里，范围只是一道归属过滤

全部模型请求记录进同一个记录库，无论它能不能归属到某个会话。列表读取的「范围」是记录上的 `attribution` 过滤（全部 / 已归属会话 / 未归属），不是切换到另一个存储。

真实环境里没有互相隔离的记录域可言：请求都来自同一台机器人在同一批会话里的真实对话，而「未归属」不是一类记录的归宿，而是采集那一刻判不出是谁在请求模型。把它做成独立记录库会带来两处代价：跨库读取要各自维护游标（两个库的序号各自单调，跨库翻页只能退回按时间比较），以及「一条记录后来能不能补上归属」这个问题被结构固定成不可能。

代价是范围过滤下推到存储层：数据库适配器需要一列 `attribution`，内存适配器需要同一份谓词。换来的是一份游标、一份容量上限、一份回收策略——三者都不需要在记录域之间做出选择。

上游 chatluna-sandbox 的记录域拆分是另一回事，不构成先例：那里的隔离由 AI 测试空间的领域边界决定，一个空间被删除时它的记录必须一起消失。本插件没有这样的边界。
