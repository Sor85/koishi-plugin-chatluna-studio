# Console 契约是唯一声明，三处用法从它派生

`src/console-contract.ts` 只有类型：端点名、入参、出参与广播载荷。服务端的监听器注册、对 `@koishijs/console` 的 `Events` 模块增强，以及客户端 `send` / `receive` 的签名全部引用同一份映射，加端点只改这一处。

**为什么值得一份专门的契约文件。** 端点名在服务端注册点、模块增强与客户端适配器上各出现一次，靠约定同步的形态是「某一处漏改」——漏掉的那处不会报错，只会在运行时收到一个没人监听的事件名。契约把三处变成一处声明加三处派生后，漏改在类型层面立刻变红。

**契约里只有形状，没有策略。** 鉴权级别（本插件统一 `authority: 4`）是注册时的决定，不是端点的形状；范围怎么翻译成归属过滤（[ADR-0001](./0001-keep-all-model-requests-in-one-library.md)）是服务端的实现，契约上只有 `scope` 这个词。

**广播频道进同一份契约。** 服务端 `broadcast` 与客户端 `receive` 因此都有类型，改载荷字段两端一起变红。新记录广播只带序号：列表当前的筛选、排序与分页只有前端知道，推整条记录会让服务端替前端猜「这条该插在哪」。

契约文件不 import 任何服务运行时，客户端引用它不会把服务端代码拖进前端产物；入参与出参一律引用既有领域类型，不在契约里复制一份形状。
