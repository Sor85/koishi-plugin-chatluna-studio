# 编辑上游预设文件并关联运行时模型证据

ChatLuna 核心预设与 Character 预设继续以各自数据目录中的 YAML 文件为权威正文，本插件不建立并行数据库副本。两类预设采用不同文档种类，编辑器保存原始源码，并通过同目录临时文件、revision 检查、文件身份复验和原子替换保护并发修改；旧 `.txt` 预设不进入本功能。

模型请求 HTTP 记录仍是“模型实际收到什么”的权威证据。插件在 ChatLuna 与 chatluna-character 的公共对话事件中复制当前运行时预设名称和模板单元，并在公共 fetch 边界把活动快照附加到唯一归属的模型请求。运行时预设快照只证明某条请求使用了哪份模板，不用于重建或覆盖请求体。

预设变量定位只对可产生文本的值表达式建立预设证据位置：服务端在明确空间中选择使用当前文档模板的最新有归属成功模型请求，不跟随当前消息页的逻辑会话或虚拟 OneBot 机器人，再通过共享模型证据投影按角色、字面锚点和表达式序号求唯一 UTF-16 文本范围，并从同一请求消息范围返回观察值与请求时间供源码编辑器悬停展示。点击仍复用该位置跳转到模型请求证据。控制标签只高亮；缺失、过期或歧义结果不得降级为字符串猜测或卡片级“伪精确”定位。

跨页面跳转使用客户端瞬时导航意图，不进入预设文件或模型请求持久化。意图消费后仍保留预设来源，直到显式返回或离开模型请求页。返回时用 CodeMirror `EditorView.scrollSnapshot` 恢复源码滚动，并用 `scroll-restore` 恢复预设列表滚动量，不重放定位。精确范围的展开、测量、滚动和强调继续通过 ADR-0012 的证据定位 adapter seam 完成，并由工作台外层详情卡片承接滚动；目标未渲染或范围无效时明确失败，不回落到其他文本。
