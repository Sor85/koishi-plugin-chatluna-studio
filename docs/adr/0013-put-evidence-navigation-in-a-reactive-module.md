# 把证据导航收进一个反应式 module

跨视图证据导航的意图发布与消费、到达闸门、返回栈、原点快照，以及「本次筛选变化不清空导航选中」这一令牌，集中在 `client/shared/evidence-navigation.ts`。它取代原先分散的 `preset-evidence-navigation.ts`、`preset-navigation-coordinator.ts`、`evidence-navigation-stack.ts` 与 `model-request-navigation.ts` 四个 module，以及 `workspace/shell.ts` 与 `model-request/workspace.vue` 中围绕它们手写的镜像状态与重复进入逻辑。导航拥有「从哪来、何时到、怎么回去」，证据定位（ADR-0012）继续拥有「最终停在哪」；两者通过 `LocateRequest { evidenceId, seq }` 相接，导航发起请求，定位负责展开、测量与滚动。

进入模型请求视图的意图统一为一个类型两种形态：必含空间归属与记录标识，可选携带证据定位段。携带证据段时导航进入到达闸门——只有目标详情标识匹配、轨迹处于单请求模式且该记录确实在轨迹内，才交出定位请求并给出「正在定位」的进行态文案；不携带证据段时意图在打开记录后立即消费。原先「从聊天消息进入」与「从预设工作台进入」两条路径各自决定筛选重置、页签、scope 构造与三次读取，逐字重复十四行，并因此只有前者设置了列表选择保护——后者在筛选 watcher 清空选中后既没有高亮，也不会把超出首屏分页的目标记录补进列表。统一进入状态后这类不对称在结构上不再可能出现。

module 独家发出四个语义互不重叠的一次性触发编号：打开某条记录、在已打开详情内定位到某条证据、恢复工作台内视图快照、恢复预设工作台原点。它们不合并成一个单调号，因为四个消费者是不同组件、在不同时机等待不同的事：详情内定位可以由预设跳转、轨迹账本选中行或组成分段点击发起，把它们收敛到同一个发号源才能让「两个互不知情的计数器喂同一个被观察的 seq」这种撞号在结构上不可能；两种恢复的等待条件不同——工作台内恢复必须等目标详情按记录身份到达，预设原点恢复在视图切换后立即生效，合并会迫使两个组件观察同一个号并各自判断这次轮不到自己。原先六个编号散落在 module、工作台 shell 与轨迹视图三处，其中预设原点恢复的类型声明在 module 里而编号由 shell 用第二个计数器补上。

本 module 用 Vue `ref` 暴露状态，这与 ADR-0012 让证据定位保持纯数据加 adapter 的选择相反，理由是两者面对的外界不同：证据定位唯一关心的事实是目标最终停在哪个滚动位置，那需要真实布局，因此它必须能在没有 DOM 的环境里被数字化假 adapter 驱动；证据导航一行 DOM、一个帧时序原语都不碰，它的全部事实是「意图是否仍然待处理、快照是否可恢复」，反应式暴露后工作台 shell 不再需要把 `canReturn` 手工镜像进三处 ref，漏一处就静默失同步的整类缺陷随之消失。仓库中质量最高的客户端行为测试正来自同样形状的 `workspace/controller.ts`。

筛选、页签、选中记录与状态文案继续由视图以 Vue `ref` 持有，module 只交出「该进入什么状态」的数据，由视图写入并发起读取，这一分工沿用 ADR-0012 的决策与状态分离：module 拥有决策，状态归持有它的那一方（证据定位的展开态后来收进了自己的 module，这条分工本身没有变）。唯一的例外是「本次筛选变化不清空导航选中」这个一次性令牌：它原先是模型请求列表选择状态上的一个字段，而消费它的筛选 watcher 属于另一个 module，两者只能靠视图里的一次 `nextTick` 对齐。令牌本身的规则已有测试覆盖，缺的是「哪些导航路径取得了保护」——那部分接线在视图里，无处断言，于是预设路径漏掉保护多年无人发现。令牌移交导航 module 并与统一进入状态绑定后消费即失效，`nextTick` 与该字段一并删除，「进入模型请求视图必然带上保护」第一次成为 module interface 上可断言的行为。

本决策不改变 ADR-0012，也不改变「区域本地状态归所属模块」这条规则：证据导航与证据定位同属跨区域行为，因此各自拥有 module，而不是被切碎回所属区域。ADR-0008 继续定义共享模型证据投影是唯一理解协议结构的 module，导航只消费证据身份与轨迹记录标识，不解释协议字段。四个原 module 的测试合并为一个，按新 interface 重写；不引入 jsdom、happy-dom 或组件挂载测试。
