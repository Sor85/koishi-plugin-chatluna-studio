# 会话名称随请求一起快照，不在读取时再查目录

一条模型请求记录带的不只是机器人与会话标识，还有采集那一刻的平台、机器人昵称、会话名称、会话类型、群号与发言者昵称。读取时不去 Koishi 运行时补名字。

理由是记录要能复盘现场：群名与昵称会改，机器人会下线，群会解散，而记录活得比它们长。读取时再查目录有两种失败形态——查不到（列表退化成一串号码）和查到了新名字（半年前的记录显示成今天的群名，用户以为自己看错了会话）。两者都不报错。

代价是同一个会话的名字会在不同记录上不一致，而这正是事实：那两条记录发生在改名前后。筛选下拉因此取最近一次出现的名字（[ADR-0001](./0001-keep-all-model-requests-in-one-library.md) 的记录库按最近若干条记录聚合可选值），列表行显示各自那条记录自带的名字。

另一处代价是记录变大：每条多出五个短字符串。相比请求体与响应原文（记录里唯一没有上限的两个字段，见 [ADR-0006](./0006-clone-and-preserve-model-response-bodies.md)），这个量级可以忽略。
