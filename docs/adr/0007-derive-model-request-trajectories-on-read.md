# 从模型请求证据派生轨迹视图

模型请求记录的领域含义是一次上游 HTTP 交互的只读证据，而 DeepSeek Harness 的 Trajectory 来自完整且追加写入的 Session Event 日志。当前插件无法在 HTTP fetch 边界可靠观测工具执行、上下文压缩、子任务和 token 级计时；把这些内容补成 DSH Session Event 会混淆事实与推测。

模型请求轨迹采用读取投影，不新增独立持久化副本：单请求轨迹从请求体和已采集响应体派生 SYSTEM、USER、ASSISTANT、TOOL 与 REQUEST 记录；会话轨迹在同一记录库中按 `conversationId` 聚合最多 200 次模型请求，每次请求作为一个 Step，并保留原始请求详情作为检查器证据。没有 `conversationId` 时，会话轨迹退化为当前单请求。

轨迹只展示现有证据可以证明的时间。每个请求使用 `createdAt` 与 `durationMs` 投影总跨度；进行中的请求不虚构结束时间，未采集 TTFT、解码时间、工具执行开始时间和嵌套关系时不生成对应跨度或关系。原始 HTTP 地址、头、请求 JSON、响应 JSON 与 SSE 原文继续由模型请求详情负责，轨迹不替代证据视图。

该方案保留模型请求记录的容量、清理、空间归属与分页语义；轨迹没有自己的生命周期，记录被回收或清理后对应投影自然消失。
