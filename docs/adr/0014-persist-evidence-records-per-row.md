# 证据记录按行持久化

模型请求记录按行持久化：每条记录一行，主键为单调序号，另有一行状态记录保存序号高水位。追加是单行 insert，补充响应体或错误是单行 update，容量回收是按序号区间 delete。整个记录数组不再作为单行 JSON 整体重写。

原先的整块写法让一次模型请求的生命周期（append 加若干次 update）触发同等次数的整表重写，每次都序列化全部记录；实测 20 次请求累计写入 19.78 MB，而单个作用域的字节上限配置为 50 MB。这既是纯粹的写放大，也让单行体积逼近数据库的单次报文上限——MySQL 的 `max_allowed_packet` 在常见部署下低于该配额，整块写法会在容量接近上限时直接失败。按行存储把单次写入压到单条记录的大小。

代价是读取路径要从「取一行再在内存里过滤」改成数据库侧查询：分页游标、按机器人与会话过滤、容量统计都需要落到 SQL 层，内存适配器也要跟着提供等价语义。ADR 0047 与 0054 定下的读取契约不变——列表仍默认从新到旧返回 50 条、单次最多 200 条，仍使用稳定序号游标，读取已回收位置仍返回 `cursor_expired` 与当前最早游标；变的只是这些语义由哪一层实现。
